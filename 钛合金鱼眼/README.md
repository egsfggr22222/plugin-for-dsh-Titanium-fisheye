# 钛合金鱼眼（Titanium Fisheye）

给 agent 一双**真正的眼睛**。

agent 默认是近视眼：它的 shell 进程没声明 DPI 感知，系统就把 1920×1080 的屏幕告诉它 1536×864。它照着这个数去画、去量，结果整体差 0.8 倍，**而且没有任何报错**。

这个插件绕开这条坏路：截图的每一条路径都先声明 DPI 感知，所以尺寸永远是物理像素。

## 三种截图

| 目标 | 看到什么 | 原理 |
|---|---|---|
| `screen` | 人眼所见 | `BitBlt` 抓桌面 DC。被窗口盖住的桌面就是被盖住的样子 |
| `desktop` | **壁纸 + 图标，被遮挡也看得见** | `PrintWindow` 让桌面窗口自己绘制到内存 |
| `window` | **某个窗口的完整内容，被遮挡也看得见** | `PrintWindow` 让该窗口自己绘制，不需要置顶或聚焦 |

最小化的窗口不截：它没有内容可绘制，还原它又会打乱用户的屏幕。

## 工具

```
eye { action: "screen" }                    全屏截图
eye { action: "desktop" }                   桌面截图（含被遮挡部分）
eye { action: "window", title: "记事本" }    按标题截一个窗口
eye { action: "window", hwnd: 123456 }      按句柄截（标题重复时用）
eye { action: "list" }                      列出所有可见窗口 + 精确边界
eye { action: "info" }                      真实屏幕尺寸
```

每次返回都带：

```json
{
  "ok": true,
  "kind": "window",
  "width": 1920,
  "height": 1030,
  "screen": { "w": 1920, "h": 1080 },
  "ink": 0.98,
  "image": "data:image/png;base64,..."
}
```

- `width` / `height` 是**这张图的真实像素**
- `screen` 是**真实桌面尺寸**，两者可以对照
- `ink` 是有效内容占比，太低说明截到了黑图

## 为什么必须校验

截图最容易出的问题是**静默错误**：图看着没问题，尺寸却不对。所以：

1. 抓完立刻量自己的输出，尺寸不符直接报错
2. 存盘后再量一次文件，确认写进去的是完整图
3. `ink` 低于阈值就判为黑图，不当作成功

宁可返回失败，也不交一张错的图。

## 已知边界

| 情况 | 结果 |
|---|---|
| 桌面被窗口遮挡 | ✅ `desktop` 可截 |
| 窗口被其他窗口遮挡 | ✅ `window` 可截 |
| 窗口最小化 | ❌ 明确报 `minimized` |
| 硬件加速窗口（部分游戏） | ⚠️ `PrintWindow` 可能返回黑图，会被 `ink` 拦下 |

## 结构

| 文件 | 作用 |
|---|---|
| `index.js` | Host：`eye` 工具、路由、结果缓存 |
| `client.js` | 浏览器：设置页（屏幕尺寸、窗口列表、最近截图） |
| `capture.ps1` | 截图引擎，纯 ASCII |

## 设置页

设置 → 左侧「钛合金鱼眼」：

- 显示真实屏幕尺寸
- 列出所有可见窗口（含最小化标记）
- 一键截全屏 / 截桌面
- 展示最近截图缩略图

## 一个必须记住的坑

**不要用 pwsh 手写截图命令。** 那条路没有 DPI 声明，截出来永远是 1536×864。

要截图，就用 `eye`。
